# Phase 3：可逆跨日编辑切片

## 范围

本切片只处理青岛 v3 旁路应用中的地点移动，不修改 Legacy v2.5.4、正式 Pages、现有高德配置或 v1.0.15 回退链。

已实现：

- 同日移动；
- 跨日移动；
- 锁定项移动与跨越保护；
- 只重算同日，或跨日操作涉及的来源日和目标日；
- 午休、地图编号、路线段、冲突和风险引用同步；
- 正向 Command 与逆向 Command；
- 会话级 Undo／Redo；
- 拖放和“上移／下移／前一天／后一天”无障碍等价操作。

未在本切片伪装完成：

- 页面重载后继续执行 Undo／Redo；
- 跨设备历史同步；
- 真实路线 Provider；
- 自定义地点、批量移动、搜索加入和完整多计划 UI。

## 数据流

```text
用户操作
  → 显式 Move Command
  → 校验来源日、目标日、地点和锁定状态
  → 重建受影响日期
  → 更新时间轴、午休、路线、冲突、编号和风险引用
  → 生成互相引用的 inverse Command
  → 记录 PlannerHistoryEntry
  → Map RenderModel 重新派生
```

Planner 不读取 DOM、地图实例或 IndexedDB。Web 只负责把拖放和按钮转换为 Command，并把新的 `TripPlan` 交给地图 Selector 与存储适配器。

## Undo／Redo 语义

每个历史项保留编辑前、编辑后两个经过 `TripPlanSchema` 校验的不可变语义快照，以及正向／逆向 Command。Undo 恢复编辑前语义，Redo 恢复编辑后语义；在 Undo 后执行新编辑会清空 Redo 分支。会话最多保留最近 50 次可撤销编辑，避免长时间操作导致内存无限增长。

当前可执行栈由 Web 会话持有。`TripPlan.editHistory` 会随保存和导出保留审计记录，但页面重载后可执行栈会重置。后续必须通过独立 Schema 和存储迁移持久化，不能把未经版本控制的递归快照直接塞入现有计划文件。

## 不变量

- 移动前后的地点集合与数量一致；
- 锁定地点不能被移动；
- 无关日期严格不变；
- 每日路线段数量等于该日地点数减一（最小为零）；
- 风险引用必须指向现存日程项；
- 地图 Marker 的日期、Item ID 和编号与日程一致；
- Undo 恢复移动前语义，Redo 恢复移动后语义；
- Provider 未接入时仍只能显示明确标注的直线降级结果。

## 回滚

本切片未被正式入口引用。回滚对应 Planner、Web、测试和文档提交即可；无需重建或重新发布 v2.5.4，也不影响 v1.0.15。
