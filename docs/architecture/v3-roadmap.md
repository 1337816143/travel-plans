## Phase 3 完成项

1. 可执行 Undo／Redo 历史已经版本化，并与计划原子保存；页面重载可恢复。
2. 高德搜索通过运行时 SDK adapter 注入，不复制 Legacy 密钥；无 SDK 时明确降级到 49 个青岛点位。
3. 自定义地点、MarkerStyle、五种编号模式和 RouteStyle 已进入共享 Schema 与编辑器。
4. 多计划、快照、归档、软删除／恢复及批量编辑已经形成 IndexedDB 闭环。
5. 住宿区域只做带警告的直线距离初筛；正式推荐仍等待真实路线与经审核动态数据。

## Phase 4 已形成的工程闭环

1. `ContentCatalog` 对 49 点、42 来源、4 季节信息、17 模块、17 预设、11 预约、3 酒店、29 愿望、7 服务候选、5 更新任务和 2 批次做运行时校验与交叉引用。
2. 内容批次状态机强制人工审核签名、冲突清零、独立发布版本和可追踪回滚。
3. 17 套预设可由确定性 Planner 生成标准 `TripPlan`，继续使用 Phase 3 全部编辑、历史和存储能力。
4. 原版 8 日恢复每日主题和核心路线点；Legacy 完整时间轴与原文继续由 v2.5.4 提供，等待无损迁移。
5. 页面明确显示 `review-required`、发布阻止和未覆盖内容类别，不把候选数据包装成正式攻略。
6. 只读生成快照对账 Legacy 的 24／8／3／17／10／12，CI 检测 canonical 数据与迁移目录漂移。
7. 医院候选使用 WGS84；药店、厕所、停车和充电只保留运行时查询，不伪造固定坐标或可用性。
8. 候选编辑器只发布到 `/v3/`；根页面仍由 v2.5.4 提供，并由聚合哈希与 `archive/v2.5.4-stable` 双重冻结。
9. `/v3/` 默认“完整攻略”精确运行冻结版 v2.5.4；“自定义规划”使用真实 Leaflet 六底图。完整页面哈希、功能入口、数据计数和真实底图由独立 parity 门禁校验。

## 下一阶段

用户侧原有能力已经通过完整攻略工作区恢复；下一步先完成人工内容审核、逐日完整时间轴／攻略正文的原生迁移与服务 Provider 决策，再进入 Phase 5 小程序 PoC。真实路线 Provider 网关需要独立 ADR 和凭据方案；它是 Planner 正式路线门禁，不允许通过复制 Legacy 前端密钥绕过。

每个切片独立提交；架构、内容数据、UI 和图标资源不混在同一提交。
