## 数据缺口

1. 现有 49 点仍以 v2.5.4 迁移数据为主体，`review-required` 状态不变。
2. 现有点位能覆盖经典景点、海滨、山岳、博物馆、历史建筑、摄影、餐饮、酒店、地铁和码头等分类，但医院、药店、卫生间、停车场、充电站等服务类别尚无正式点位。当前 7 项旁路候选不计入49点：3个医院候选有官方地址和WGS84坐标，其他4类必须运行时查询。
3. `module-laoshan-other-candidate` 只有大河东服务锚点，明确不虚构巨峰、仰口、华严或九水线路；这些线路须在正式点位和官方约束录入后再扩展。
4. 24 项 Legacy 来源已经一对一迁入并保留原名称、URL 和说明，但仍是历史观察；重复链接尚未在人工审核后归并。
5. 8 项 Legacy 预约已连同日期、点位、级别、可选性、说明和渠道原样迁入；加上 3 项治理规则共 11 项。所有规则仍需按目标日期复核。
6. 3 家酒店的名称、地址、位置说明、评分文字和库存警告已经无损迁入；评分、房态、早餐和退改没有被升级为当前事实。Phase 3 住宿功能仍只是带警告的区域初筛。
7. 17 项必去和 12 项必吃必买已迁入候选实体，10 个愿望地图点继续复用49点基线；商户、供应、价格和营业状态仍需人工与运行时复核。

## 动态与 Provider 缺口

- 崂山开放／限流、博物馆开放／预约、地铁运营、浴场安全、海上航线已建立更新任务，但任务不会自动发布结果。
- 当前 v3 路线仍为 `straight-line-fallback`；不能显示为真实道路距离或交通时间。
- 天气、路况、实时班次、票价、酒店库存、商户营业和排队没有被写入固定内容。
- 新 v3 未复制或扩大 Legacy 高德 Web Service 密钥；服务端／网关方案仍需独立 ADR。

## 状态、存储、地图、构建与小程序影响

- 状态：预设生成标准 `TripPlan`，继续使用显式 Command 和版本化 Undo／Redo；内容审核状态不存入 DOM。
- 存储：IndexedDB 多计划与导入导出保持 Phase 3 语义；内容候选包目前随构建只读加载，不覆盖用户计划。
- 地图：Marker Logo 与编号仍独立；Phase 4 不修改 Legacy Leaflet／高德、多底图、cluster、天气或导航。
- 构建：`@qingdao/content` 进入 strict TypeScript、ESLint、Prettier、Vitest、bundle budget 和 secrets scan；v2 构建链不变。
- 小程序：尚未开始 Phase 5 PoC；本阶段数据、Schema 和 Planner 可共享，但这不是地图、拖动或真机兼容性证据。

## 人工审核清单

正式审批候选批次前至少需要：

1. 逐条打开官方链接，记录审核人、审核时间和冲突处理；
2. 对开放、票价、预约、班次和季节字段设置合理 TTL；
3. 核验所有美食愿望点的门店身份、地址、独立证据和推广风险；
4. 对 17 个模块逐项确认体力、停留、拆分、冲突和 Plan B；
5. 对原版 8 日与 v2.5.4 的每日核心路线进行自动和人工对账；
6. 将快照与 canonical Legacy 数据对账，并人工确认 24／8／3／17／10／12 的语义没有遗漏；
7. 核验3个医院候选的入口与服务范围，确认药店／厕所／停车／充电Provider方案；
8. 关闭两个批次的全部冲突后，才能签名 `approved`；发布必须产生独立 release manifest。

## 结论

Phase 4 的工程闭环和本轮 Legacy 五类内容迁移已经建立，但候选内容没有人工审核，正式发布门禁仍未满足。当前正确状态是“无损迁移已验证、可展示、可测试、禁止发布”，不是“青岛完整攻略库已经完成”。
